# MapaGator

MapaGator is our COP 3530 group project for group 112. We use road data from OpenStreetMap to compare **Prim's** and **Kruskal's** algorithms on the same network. Intersections are vertices, roads are weighted edges, and the goal is to connect the network at the lowest total cost. There is also an SFML dashboard for exploring the map and a command-line program for quick runs and benchmarks.

**You can build and test this project without downloading Florida road data or installing SFML.** Start with the included sample graph to confirm the C++ build works, then set up the optional map viewer and Gainesville dataset.

## 1. Build the command-line program and Catch2 tests

### Windows: MSYS2 UCRT64 / MinGW

Open **PowerShell in the folder containing `CMakeLists.txt`**. First check the tools:

```powershell
cmake --version
g++ --version
where.exe mingw32-make
```

If `mingw32-make` is missing, install the UCRT64 toolchain using MSYS2's UCRT64 shell, or use a working Ninja installation and select `-G "Ninja"` instead. A C++ compiler by itself does not provide the Make build tool.

For the first configuration, use a **new build folder**. We use `build-mingw` here to avoid mixing it up with older CMake attempts:

```powershell
cmake -S . -B build-mingw -G "MinGW Makefiles" `
  -DCMAKE_C_COMPILER="C:/msys64/ucrt64/bin/gcc.exe" `
  -DCMAKE_CXX_COMPILER="C:/msys64/ucrt64/bin/g++.exe" `
  -DMAPAGATOR_BUILD_TESTS=ON `
  -DMAPAGATOR_BUILD_SFML=OFF
```

Then **build before trying to run CTest**:

```powershell
cmake --build build-mingw --parallel 4
ctest --test-dir build-mingw --output-on-failure
```

When the tests are built and registered properly, CTest should list **12 individual test cases**. You can also run the test executable directly:

```powershell
.\build-mingw\MapaGatorTests.exe
```

To run the CLI on the included sample graph:

```powershell
.\build-mingw\MapaGator.exe --graph data\sample_graph.txt `
  --vertices data\sample_vertices.txt --algorithm both `
  --svg sample_map.svg
```

Prim and Kruskal should agree on the minimum cost. Open `sample_map.svg` in a browser to see the selected roads without installing SFML.

### Visual Studio or other operating systems

For Visual Studio C++ on Windows, open a **Developer PowerShell** with the C++ build tools installed and configure into a different folder:

```powershell
cmake -S . -B build-vs -G "Visual Studio 17 2022" -A x64 `
  -DMAPAGATOR_BUILD_TESTS=ON -DMAPAGATOR_BUILD_SFML=OFF
cmake --build build-vs --config Release
ctest --test-dir build-vs -C Release --output-on-failure
```

For Linux/macOS with a working C++17 compiler and CMake, a typical build is:

```bash
cmake -S . -B build -DMAPAGATOR_BUILD_TESTS=ON -DMAPAGATOR_BUILD_SFML=OFF
cmake --build build --parallel 4
ctest --test-dir build --output-on-failure
```

On multi-configuration generators such as Visual Studio, the programs may be under `build-vs/Release/` rather than directly inside the build folder.

## 2. Enable the interactive SFML map

This viewer was written for **SFML 2.x**. It will not build against SFML 3 without changes. Make sure SFML is compatible with the compiler you are using: do not mix a Visual Studio library with your MSYS2 GCC build.

If using **MSYS2 UCRT64 GCC** and you do not already have a matching SFML 2.6.2 installation, download the **source** archive of SFML 2.6.2. The extracted folder must contain `CMakeLists.txt`, `include/`, and `src/`. A precompiled download containing only `bin/`, `include/`, and `lib/` is not the same as the source archive.

SFML can live anywhere outside the repository. This example uses `C:\Libraries`, which you can create yourself, but it is **not** a required Windows folder:

```powershell
cmake -S "C:/Libraries/SFML-2.6.2" -B "C:/Libraries/SFML-build" `
  -G "MinGW Makefiles" `
  -DCMAKE_C_COMPILER="C:/msys64/ucrt64/bin/gcc.exe" `
  -DCMAKE_CXX_COMPILER="C:/msys64/ucrt64/bin/g++.exe" `
  -DCMAKE_BUILD_TYPE=Release `
  -DCMAKE_INSTALL_PREFIX="C:/Libraries/SFML-install" `
  -DBUILD_SHARED_LIBS=ON `
  -DSFML_BUILD_AUDIO=OFF -DSFML_BUILD_NETWORK=OFF `
  -DSFML_BUILD_EXAMPLES=OFF -DSFML_BUILD_DOC=OFF
cmake --build "C:/Libraries/SFML-build" --parallel 4
cmake --install "C:/Libraries/SFML-build"
```

Once installed, enable the viewer **using the same existing MinGW build directory**:

```powershell
cmake -S . -B build-mingw -G "MinGW Makefiles" `
  -DMAPAGATOR_BUILD_TESTS=ON `
  -DMAPAGATOR_BUILD_SFML=ON `
  -DSFML_DIR="C:/Libraries/SFML-install/lib/cmake/SFML"
cmake --build build-mingw --parallel 4
```

If SFML is installed somewhere else, change `SFML_DIR` to the folder containing its `SFMLConfig.cmake`. Do not use `C:\Libraries` on a teammate's machine unless they actually installed SFML there.

For a shared/dynamic SFML build, Windows must find the SFML DLLs. In the terminal where you launch the GUI:

```powershell
$env:PATH = "C:\Libraries\SFML-install\bin;$env:PATH"
.\build-mingw\MapaGatorGUI.exe data\sample_graph.txt data\sample_vertices.txt
```

**RUN THIS After preprocessing city:**

```powershell
.\build-mingw\MapaGatorGUI.exe data\graph_data.txt data\vertices.txt
```

**Dashboard controls:** mouse wheel to zoom around the cursor, left-drag to pan, `F` to fit, `P`/`K` for Prim/Kruskal, and `1`/`2`/`3` for length/fiber/flood weighting. Use **Shift + left-click** to close or reopen a road, right-click to toggle an anchor, `H` to start a hub connection, `R` to reset changes, and `Esc` to exit. The main actions also have sidebar buttons.

## 3. Prepare Gainesville (or any city) road data
Check out the [OSM Data extracts](https://download.geofabrik.de/).


The Florida `.osm.pbf` file cannot be opened directly by `MapaGator.exe` or `MapaGatorGUI.exe`. The Python script converts it into the graph and coordinate files these programs read.

Use a Python environment that can install the required packages:

```powershell
python -m pip install osmnx pyrosm geopandas
python -c "import osmnx, pyrosm, geopandas; print('Python dependencies available')"
```

If the import fails even though `pip install` succeeded, VS Code/PowerShell may be using a different Python interpreter. Check `python -c "import sys; print(sys.executable)"`, then run both `-m pip` and the script with that **same interpreter**. On the original development computer, a separate Python 3.13 interpreter was used rather than `C:\msys64\ucrt64\bin\python.exe`; do not assume that path exists on other machines.

Below is an example of a another solution: 
Just replace what comes after the ampersand with the path of your working python interpret
```powershell
& "C:\Users\user\AppData\Local\Programs\Python\Python313\python.exe" -m pip install osmnx pyrosm pandas

```

With the Florida dataset already downloaded, from the **project root** run:

```powershell
python scripts\file_preprocessing.py `
  --pbf "C:\path\to\florida.osm.pbf" `
  --places "Gainesville, Florida, USA" `
  --out data
```

Replace the example PBF path with the real location of your downloaded file. The script also supports downloading the region with OSMnx (internet required):

```powershell
python scripts\file_preprocessing.py --download `
  --places "Gainesville, Florida, USA" --out data
```

The script writes:

- `data/graph_data.txt`: graph size followed by road records and weights
- `data/vertices.txt`: vertex IDs followed by latitude and longitude

Check the files before launching the GUI:

```powershell
Test-Path .\data\graph_data.txt
Test-Path .\data\vertices.txt
Get-Content .\data\graph_data.txt -TotalCount 3
```

Both `Test-Path` commands should return `True`. The script needs internet access to resolve the Gainesville boundary through OSMnx, even when the roads come from a local Florida PBF. Statewide files can also use substantial memory during processing.

Flood weights require actual road risk data. Optionally pass `--risk-csv file.csv` where the columns are `osm_u,osm_v,risk`. Without risk data, the script assigns zero flood risk, so the flood scenario has the same weights as length-only. The fiber multipliers are examples for comparing algorithms, not actual construction quotes.

## Troubleshooting

These are the problems we ran into while setting the project up. Check the first error in a failed configure/build command rather than repeatedly running different configurations in the same build directory.

| Message or symptom | What to do |
| --- | --- |
| **`nmake -?` / `nmake` not found** | CMake selected Microsoft's NMake instead of MinGW. Use `-G "MinGW Makefiles"` in a **new** build directory, such as `build-mingw`. |
| **`CMAKE_CXX_COMPILER not set`** | Configure with the correct compiler path, e.g. `C:/msys64/ucrt64/bin/g++.exe`, and confirm `g++ --version` works. |
| **`Could not create named generator MinGW MakeFiles`** | Generator spelling matters: use exactly **`MinGW Makefiles`** (lowercase `f` in `Makefiles`). |
| **`nmake` still appears after changing `-G`** | The old directory cached the NMake generator. Pick a new `-B` directory or delete **only the generated build folder** and reconfigure. Do not delete project source files. |
| **`build-new is not a directory`** | Use the **actual build folder name**. The commands in this README consistently use `build-mingw`. CMake creates it during the configure step. |
| **`MapaGatorTests_NOT_BUILT-...` in CTest** | CTest registered a placeholder because the test executable was not built/discovered. Run `cmake --build build-mingw --target MapaGatorTests --parallel 4` **before** CTest. If the build fails, fix the **first compiler error**. |
| **CTest only lists 1 `_NOT_BUILT` test instead of 12** | Build the test target, then rerun `ctest --test-dir build-mingw --output-on-failure`. A clean build directory may be needed after a failed or moved build. |
| **Compile error mentioning `file.close()` in graph-loading test** | In the supplied test file, the temporary output streams end inside braces. No extra `file.close()` is needed outside those braces. The SVG test separately closes its **input** stream before deleting the SVG on Windows. |
| **SVG test fails: file is used by another process** | Make sure `std::ifstream` is closed before `std::filesystem::remove`. The provided test includes that fix. |
| **`SFMLConfig.cmake` not found** | Check SFML was actually installed and pass the correct `SFML_DIR`, matching your compiler and SFML **2.x** version. |
| **SFML source download has no `CMakeLists.txt`** | Check for an extra nested folder; otherwise download the **source archive**, not a precompiled package. |
| **DLL missing when opening GUI** | Add your SFML installation's `bin` directory to the current terminal's `$env:PATH`, or arrange for the DLLs to be alongside the executable. |
| **`Could not open graph file: data\\graph_data.txt`** | Run the Python preprocessing step first. Test the GUI with `data\\sample_graph.txt` and `data\\sample_vertices.txt` before using Gainesville. |
| **`ModuleNotFoundError: osmnx` or `pyrosm`** | Install packages with `python -m pip` using the same interpreter that launches `file_preprocessing.py`. |
| **`No module named pip` from MSYS2 Python** | Switch to a Python installation with pip, or set up pip for that interpreter. Avoid mixing different Python environments. |
| **`File does not exist: florida-....osm.pbf`** | Pass the actual file's absolute path to `--pbf`. Verify it exists with `Test-Path`. |

To start over after a source reorganization, you can **delete only a generated build directory** and configure a fresh one. Do **not** run `cmake -G "MinGW Makefiles" .` in the project root: it puts cache files next to the source. Always prefer `cmake -S . -B build-mingw ...`.

If CMake is allowed to download Catch2, the first configuration needs internet. To build without tests, pass `-DMAPAGATOR_BUILD_TESTS=OFF`. To build without the GUI, pass `-DMAPAGATOR_BUILD_SFML=OFF`. Those switches do not change the MST algorithms.

## Notes on the implementation

- Prim uses our custom binary min-heap and the adjacency list. Kruskal sorts the edge list and uses Union-Find with path compression and union by rank.
- Both return a **minimum spanning forest** when the road network is disconnected. Equal-cost roads can lead to different edge choices even when the final total is the same.
- We treat roads as undirected for MST purposes, even if OpenStreetMap marks one-way driving restrictions.
- Physical length is stored separately from cost, so changing scenarios does not change mileage.
- Multiple anchors are connected through a temporary zero-cost virtual vertex. Synthetic anchor edges are removed from the physical output.
- Benchmarks measure the algorithm running on the machine and graph used; results will differ across computers.
